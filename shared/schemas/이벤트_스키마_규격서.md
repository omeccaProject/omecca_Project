# 오메카3 프로젝트 — 공통 이벤트 스키마 규격서

작성: 장성혁 · 최종 확인: 2026-08-06 (b_gateway 코드 기준 검증 완료)

## 1. 목적

YOLOv11(탐지) · 얼굴인식/흉기 · LPR(번호판) · ByteTrack(추적) · 궤적분석(음주운전) 등
각 모듈에서 발생하는 위험 이벤트를 하나의 표준 포맷으로 통일하기 위한 문서입니다.

모든 모듈은 이 스키마 형태로 `b_gateway`의 `POST /api/events`에 이벤트를 전송합니다.
이후 저장 → 실시간 알림(WebSocket) → 증거 리포트(PDF) 생성까지 동일한 구조를 재사용합니다.

각 담당자는 본인이 개발하는 탐지 로직의 결과를 아래 포맷에 맞춰 전송해 주세요.
필드가 부족하면 임의로 새 최상위 필드를 추가하지 말고, `meta` 안에 확장하거나
담당자(장성혁)에게 요청 바랍니다.

## 2. 이벤트 페이로드 예시 (JSON)

```json
{
  "camId": "CAM-01",
  "trackId": "trk-1234",
  "eventType": "UNREGISTERED_VEHICLE",
  "objectClass": "VEHICLE",
  "bbox": [120, 80, 90, 140],
  "confidence": 0.93,
  "occurredAt": "2026-08-06T10:12:33",
  "location": { "lat": 37.5326, "lng": 127.0246 },
  "isRegisteredTarget": false,
  "targetId": null,
  "roiId": null,
  "meta": {
    "plateNumber": "12가3456",
    "matchedDbId": "wanted_001",
    "faceMatchScore": 0.87,
    "stationaryDurationSec": null,
    "trajectoryFeatures": {
      "zigzagCount": null,
      "accelDecelCount": null,
      "speedVarianceKmh": null
    }
  },
  "frameRefBefore": "s3://.../before.jpg",
  "frameRefAfter": "s3://.../after.jpg"
}
```

## 3. 필드 상세 설명

### 3.1 공통 식별·탐지 정보

| 필드명 | 타입 | 설명 |
|---|---|---|
| `camId` | string | 탐지가 발생한 CCTV 고유 ID |
| `trackId` | string \| null | 동일 대상을 프레임 간·다중 CCTV 간 추적할 때 부여되는 ID (ByteTrack) |
| `eventType` | enum | 아래 3.2 참고 |
| `objectClass` | enum | 아래 3.3 참고 |
| `bbox` | [x, y, w, h] | 탐지 객체의 프레임 내 바운딩 박스 좌표 (정수 4개) |
| `confidence` | float (0~1) | 탐지 신뢰도 |
| `occurredAt` | ISO 8601 문자열 | 이벤트 실제 발생 시각 |
| `location` | `{ lat, lng }` | 이벤트 발생 위치 좌표 (문자열 아님, 반드시 좌표 객체) |

### 3.2 eventType (7종)

| 값 | 의미 | 관련 기능 |
|---|---|---|
| `WANTED_PERSON` | 수배자 얼굴 인식 | ① |
| `WEAPON` | 흉기 인식 | ① |
| `UNREGISTERED_VEHICLE` | DB 미등록 차량 | ④ |
| `DEBRIS` | 도로 낙하물·방치물 | ⑤ |
| `DUI_PATTERN` | 음주운전 의심 주행 패턴 | ⑥ |
| `SIGNAL_VIOLATION` | 신호 위반 | ⑦ |
| `UTURN_VIOLATION` | 불법 유턴 | ⑦ |

> 위 7종 외의 값(예: `FALLING_OBJECT`, `ILLEGAL_UTURN`, `TRACKING`)은 사용하지 않습니다.

### 3.3 objectClass (3종)

| 값 | 의미 |
|---|---|
| `PERSON` | 사람 |
| `VEHICLE` | 차량 |
| `OBJECT` | 사물 |

세부 종류(흉기, 트럭, 킥보드 등)는 `objectClass`에 넣지 않고 `meta`에 담습니다.

### 3.4 관심 대상 추적 관련

| 필드명 | 타입 | 설명 |
|---|---|---|
| `isRegisteredTarget` | boolean | 관제요원이 등록한 관심 대상과 관련된 이벤트인지 여부 |
| `targetId` | long \| null | 관심 대상 등록 건의 ID (`trackId`와는 별개 개념) |

### 3.5 ROI 관련

| 필드명 | 타입 | 설명 |
|---|---|---|
| `roiId` | long \| null | 낙하물(⑤)·신호위반/유턴(⑦) 판정 시 트리거된 ROI/가상 라인 ID |

### 3.6 meta (이벤트 유형별 가변 필드)

`eventType`마다 필요한 부가 정보가 다르므로 `meta` 객체로 유연하게 확장합니다.

| 필드명 | 설명 |
|---|---|
| `plateNumber` | 인식된 차량 번호판 |
| `matchedDbId` | 수배자/차량 DB에서 매칭된 레코드 ID |
| `faceMatchScore` | 수배자 얼굴 인식 유사도 (0~1) |
| `stationaryDurationSec` | ROI 내 정지 지속 시간(초) — 낙하물 판별 근거 |
| `trajectoryFeatures` | 음주운전 의심 패턴 근거 (`zigzagCount`, `accelDecelCount`, `speedVarianceKmh`) |

### 3.7 증거 자료

| 필드명 | 타입 | 설명 |
|---|---|---|
| `frameRefBefore` | string | 이벤트 발생 직전 캡쳐 이미지 경로 |
| `frameRefAfter` | string | 이벤트 발생 직후 캡쳐 이미지 경로 |

## 4. 설계 원칙

- 공통 필드와 가변 필드(`meta`)를 분리해, 새 기능이 추가돼도 API/DB 구조를 바꾸지 않아도 됩니다.
- `trackId`(프레임 간 추적 단위) ≠ `targetId`(관제요원이 등록한 감시 대상) ≠ 서버가 발급하는 이벤트 PK. 세 개념을 혼용하지 않습니다.
- `location`은 항상 좌표 객체(`{lat, lng}`)이며 문자열 주소가 아닙니다.

## 5. 연동 상태

`b_gateway`의 `POST /api/events`가 이 스키마를 그대로 수신하도록 구현되어 있습니다
(`EventCreateRequest` 참고). 검증 실패 시(잘못된 `eventType`/`objectClass` 값 등) 400 응답을 반환합니다.
